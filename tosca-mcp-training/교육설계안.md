# Tosca Commander MCP 입문 교육 설계안

## 1. 교육 개요

| 항목 | 내용 |
|------|------|
| 과정명 | Tosca Commander MCP 입문: VS Code + GitHub Copilot으로 테스트케이스 만들기 |
| 대상 | Tosca를 써 본 경험이 적은 테스터, QA 담당자 (MCP는 처음) |
| 형식 | 강의 + 개인 실습 (1인 1PC) |
| 시간 | 3시간 20분 (휴식 10분 포함) |
| 결과물 | 강의 슬라이드(.pptx, 제공받은 디자인 템플릿 적용), 실습 워크북(.docx) |
| 기준 버전 | Tosca Commander 2026.1 LTS Patch 1 이상, Tricentis commander-mcp 스킬팩 1.2.1 |
| AI 클라이언트 | VS Code + GitHub Copilot (다른 클라이언트는 다루지 않음) |
| 실습 내용 | 강사가 채운다. 이 자료에는 슬라이드와 워크북의 실습 틀만 들어 있다 |

## 2. 대상 분석과 설계 방향

교육 대상은 다음 두 가지를 모두 모른다고 가정한다.

1. Tosca 기본 구조(Module, TestCase, TestStep, ActionMode, ScratchBook, ExecutionList)
2. MCP가 무엇이고 AI 어시스턴트가 어떻게 외부 프로그램을 조작하는지

그래서 설계 방향을 이렇게 잡았다.

- MCP 개념 설명 전에 Tosca 용어를 5분 정도 먼저 짚는다. 용어를 모르면 AI가 돌려주는 답을 읽을 수 없다.
- 이론은 "무엇을 할 수 있고, 무엇은 사람이 해야 하는가"까지만 다룬다. 프로토콜 세부 구조는 다루지 않는다.
- 실습은 되돌리기 쉬운 작업(조회)부터 만들기, 실행, 저장 순서로 배치하기를 권한다. 실습 내용은 강사가 틀에 채운다.
- 실습마다 "AI에게 먼저 계획을 받고, 확인한 뒤 실행"하는 습관을 반복해서 만든다.
- 프롬프트 템플릿은 Tricentis 공식 스킬팩에 들어 있는 워크플로 템플릿 18종에 1:1로 대응시켜, 사내 템플릿으로 바로 쓸 수 있게 만든다.

## 3. 학습 목표

교육이 끝나면 수강자는 다음을 할 수 있다.

1. Tosca MCP Server가 Commander와 AI 어시스턴트 사이에서 하는 역할을 설명한다.
2. VS Code의 GitHub Copilot을 Commander MCP Server(`http://127.0.0.1:46248/mcp`)에 연결하고, 도구 실행 확인 창에서 입력값을 보고 허용한다.
3. 기존 모듈을 재사용해 수동/자동 테스트케이스를 프롬프트로 만들고, ScratchBook에서 검증한다.
4. 대상·작업·조건·확인 4요소로 프롬프트를 작성하고, 제공된 템플릿을 업무에 맞게 고쳐 쓴다.

## 7. 실습 설계

실습 내용은 강사가 채운다. 이 자료는 슬라이드 18~32와 워크북 2.5, 3장에 들어갈 틀과, 어떤 내용이 와도 지켜야 할 원칙만 담았다.

- 대괄호 `[ ]`는 채울 자리다. 슬라이드에서 바로 고쳐도 되고, `src/content.js`의 `labs`를 고친 뒤 다시 빌드하면 슬라이드와 워크북이 같이 바뀐다.
- AI는 화면을 스캔해 UI 모듈을 만들지 못한다. 실습에 쓸 모듈은 강사가 미리 XScan으로 스캔해 둔다. (API 모듈은 MCP 도구로 만들 수 있다.)
- 비밀번호는 프롬프트에 쓰지 않는다. TCP에 넣어 두고 `{CP[이름]}`으로 참조하게 해서, 민감 정보를 클라우드 모델로 보내지 않는다.
- 바꾸는 작업은 계획부터 받고 승인한다. 도구 실행 확인 창에서는 입력값을 펼쳐 보고 허용한다(슬라이드 16, 워크북 2.4).
- `create_test_cases`로 만든 테스트케이스는 만들 때 바로 저장된다. 저장을 따로 요청해야 하는 것은 `set_attribute` 같은 수정이다. 실행은 저장된 상태로 돈다.
- 실습은 처음부터 끝까지 VS Code의 한 채팅 세션에서 진행한다. 바뀐 객체 목록을 알려 주는 도구가 없어서 AI가 대화 기록에 의존하기 때문이다.

## 8. 프롬프트 템플릿 설계

- 구분: Tricentis가 제공하는 것은 AI용 워크플로 템플릿 18종이고, 사람용 프롬프트 템플릿 T00~T18은 이 과정에서 만든 것이다. 슬라이드와 워크북에 이 구분을 명시한다.
- T00 공통 머리말: 새 채팅을 열 때 먼저 붙이는 규칙(계획 먼저, 경로 명시, 삭제·체크인 전 확인, 작업 상태·이름은 set_attribute로). VS Code용 스킬팩은 짧은 지침 파일만 설치하고 워크플로 문서는 넣지 않으므로 T00이 그 규칙을 대신 전한다.
- T01~T18: commander-mcp 스킬팩 `reference/workflows-index.md`의 18개 워크플로와 순서·이름을 맞춘다.
- 각 템플릿 항목: 언제 쓰나 / 프롬프트 본문([ ] 빈칸) / 작성 예시 / AI가 주로 쓰는 도구 / 확인할 점.

## 9. 디자인 원칙

- 슬라이드는 제공받은 디자인 템플릿의 마스터·레이아웃·테마·이미지를 그대로 쓴다. 원본 슬라이드의 내용은 쓰지 않는다.
- 글꼴: Open Sans(영문) + Noto Sans CJK KR(한글). 제목 31pt 파랑(004C97), 본문 18~23pt 회색(4E4F51), 각주 12.5pt.
- 구성 요소는 템플릿에 있는 것만 쓴다: 3단 규칙선(0E88AE·D2D755), 남색 머리행 표(004C97, F1F5F9 줄무늬), 연회색 상자(F1F5F9)와 › 흐름, 남색 번호 사각형, LAB 화면(목표 띠·진행 순서·완료 확인·시간), 화면 도식(남색 머리띠), 하단 각주와 꼬리말.
- 슬라이드 문장은 템플릿과 같이 '~합니다'체로 쓴다. 워크북 표 안의 짧은 서술은 '~한다'체를 유지한다.
- 피할 것: 이모지, 과장된 수식어("혁신적", "강력한", "손쉽게"), 근거 없는 수치.

## 11. 가정과 확인 필요 사항

- "현재 만들어져 있는 프롬프트 템플릿"은 Tricentis 공식 스킬팩에 포함된 워크플로 템플릿 18종을 기준으로 정리하고, 각각에 맞는 사람용 프롬프트 템플릿을 새로 만들었다. 사내에서 따로 만든 템플릿이 있으면 워크북 5장 형식에 맞춰 추가하면 된다.
- 도구 목록은 스킬팩 1.2.1 기준이다. 실제 목록은 Commander 패치에 따라 다를 수 있으므로 VS Code의 Open Customizations → Tools에서 직접 확인한다.
- VS Code 메뉴 이름(MCP: Add Server, Copilot Global, Open Customizations 등)은 2026년 10월 문서 기준이다. VS Code 업데이트로 이름이 바뀔 수 있으니 교육 전에 한 번 따라 해 본다.
- VS Code는 Agent Skills(`.github/skills/`)도 지원하지만, Tricentis는 VS Code용으로 지침 파일만 안내한다. 이 과정은 Tricentis 안내를 따랐다.
