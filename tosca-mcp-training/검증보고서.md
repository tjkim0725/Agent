## 2. 이번 변경: VS Code + GitHub Copilot만 남기기, 실습은 틀로

**클라이언트 내용**

- Cursor, Claude Code, Claude Desktop 설정과 언급을 모두 뺐다. MCP 역사(2024년 11월 Anthropic 공개)는 클라이언트 설명이 아니라서 남겼다.
- VS Code 연결은 2026년 10월 VS Code 문서 기준으로 새로 썼다. MCP: Add Server → HTTP → 서버 ID `tosca-commander` → Global → Copilot Global 순서이고, `~/.copilot/mcp-config.json`에 `mcpServers` 형식으로 저장된다. 예전 형식인 `.vscode/mcp.json`(`servers` 키)과 섞지 말라는 안내를 넣었다.
- 새 슬라이드 16과 워크북 2.4: Copilot의 도구 실행 확인 창과 허용 범위, 권한 수준(Manual permissions 유지, Allow all·Autopilot 쓰지 않음), Chat: Reset Tool Confirmations, 서버 로그(Show Output).
- 준비물과 사전 점검에 회사 Copilot 계정의 조직 정책 'MCP servers in Copilot'(기본값 꺼짐) 확인을 넣었다.
- 스킬팩은 VS Code용 팩만 안내한다. 프로젝트 폴더에만 설치되고(`-Ide VSCode -Scope Project`), 지침 파일만 들어가며 워크플로 문서 18종은 들어가지 않는다. 그래서 T00 공통 머리말을 새 채팅마다 붙이도록 슬라이드 42, 44와 워크북 2.3, 5장 설명을 고쳤다.
- 문제 해결 표에 VS Code 증상 3가지를 더했다(도구가 안 보임, 서버가 시작되지 않음, 정책으로 막힘). 전체 10가지.

**실습 내용**

- Demo Web Shop 로그인 시나리오(Lab 0~5의 프롬프트, 계획 표, 화면 예시, 확인 포인트, 강사 준비 항목)를 모두 뺐다.
- 대신 Lab 1~6 틀을 넣었다. 슬라이드는 Lab마다 개요(목표, 진행 순서, 완료 확인, 시간)와 프롬프트·결과 예시 두 장, 워크북은 Lab마다 목표, 준비, 진행 순서, 프롬프트, 도구, 결과 예시 칸, 확인 포인트, 결과 기록, 막히면이 있다. 채울 자리는 모두 `[ ]`로 표시했다.
- 실습 대상(슬라이드 18)과 실습 환경(워크북 2.5)도 틀로 바꿨다. 어떤 실습이 와도 지켜야 할 원칙(모듈은 미리 XScan, 비밀번호는 TCP `{CP[이름]}` 참조, 한 채팅 세션에서 진행)은 고정 문구로 남겼다.
- 실습 밖에 있던 예시도 실습과 겹치지 않게 바꿨다. 예시 경로 `TestCases/MCP실습`은 `TestCases/회원`으로, Lab을 가리키던 템플릿 예시(T05, T06, T16)는 독립된 예시 문장으로 바꿨다.
- Lab 수와 휴식 위치는 `src/content.js`의 `LAB_COUNT`, `BREAK_AFTER`로 정한다. Lab 하나를 채워 다시 빌드하면 슬라이드와 워크북에 같이 들어가는 것을 시험해 확인했다.

## 3. 디자인 템플릿 적용

제공받은 `01_Tosca_Customer_4H_DemoWebShop.pptx`는 디자인만 쓰고 내용은 쓰지 않았다.

- 원본에서 슬라이드를 모두 뺀 기반 파일(`src/template/tricentis_base.pptx`)을 만들고, 그 위에 46장을 새로 만들었다. 남긴 것은 슬라이드 마스터, 레이아웃 22종, 테마(색·글꼴), 마스터·레이아웃이 쓰는 이미지 7개뿐이다.
- 쓴 레이아웃: Title Slide(표지), Section Header(파트 구분 4장과 휴식), Title Only, Comparison, Three Content.
- 원본의 배치 규칙을 따랐다: 제목 위치·크기·색(31pt, 004C97), 본문 회색(4E4F51), 청록·연두 규칙선, 남색 머리행 표, 번호 사각형 목록, LAB 화면, 화면 도식, 각주와 워크북 참조 표시, 꼬리말과 쪽 번호(자동 번호 필드). 한글 글꼴은 원본과 같은 Noto Sans CJK KR이다.
- 원본 파일에 남아 있던 메타데이터(다른 문서의 슬라이드 제목 목록, 작성자·작성일, 미리보기 그림, 변경 기록 연결, 구역 목록)를 지웠다.

## 4. 자동 검증 (`src/verify.py`, 55개 항목 전부 통과)

- 교육자료의 도구 32개가 스킬팩 `reference/tools-index.md`와 정확히 일치
- 본문에 나오는 도구·파라미터 이름(snake_case)이 모두 실제 이름
- T01~T18이 가리키는 워크플로 파일 18개가 모두 존재하고, 순서가 `workflows-index.md`와 같음
- 템플릿 19개(T00 포함)가 워크북에, T06 본문이 슬라이드에 같은 문구로 들어 있음
- Lab 1~6 틀이 슬라이드(개요, 프롬프트)와 워크북에 모두 있음
- 슬라이드, 워크북, 발표자 노트 어디에도 Cursor, Claude(Code·Desktop), Windsurf, mcp-remote가 없음
- VS Code 설정 항목(MCP: Add Server, Copilot Global, mcp-config.json, Open Customizations, MCP servers in Copilot, Manual permissions, `-Ide VSCode`)이 들어 있음
- 예전 실습 내용(MCP실습 폴더, Demo Web Shop, DWS_Password 등)이 남아 있지 않음
- 46장 모두 발표자 노트 있음
- 이모지, 문장 속 줄표, 느낌표, 상투적 과장 표현 없음

두 파일 모두 Office 스키마 검사(validate.py)를 통과했다.

## 8. 교육 전에 강사가 확인할 것

- 실습 내용 채우기: 슬라이드 18~32, 워크북 2.1의 대괄호 항목 2개, 2.5, 3장. 3시간 20분 시간표의 실습 결과 칸(슬라이드 3)도 채운다.
- VS Code 메뉴 이름: 2026년 10월 문서 기준이다. 교육 PC의 VS Code에서 MCP: Add Server부터 도구 확인 창까지 한 번 따라 해 본다. 도구 확인 창 모양은 버전에 따라 다르다.
- 회사 Copilot 정책: 'MCP servers in Copilot'이 허용됐는지, VS Code 관리 정책(MCP 허용 목록)이 있다면 tosca-commander가 허용되는지 관리자에게 확인한다.
- VS Code와 스킬: VS Code는 Agent Skills(`.github/skills/`)도 지원하지만 Tricentis는 VS Code용으로 지침 파일만 안내한다. 스킬 폴더를 따로 넣어 쓸지는 사내에서 시험한 뒤 정한다.
- 발표 PC 글꼴: Open Sans와 Noto Sans CJK KR이 없으면 PowerPoint가 다른 글꼴로 바꿔 보여 준다. 발표 PC에서 한 번 넘겨 본다.
- 실제 도구 목록: Commander 패치에 따라 다를 수 있으므로 Open Customizations → Tools에서 확인한다.
- ExecutionList 실행(T08): 2026.1 문서와 스킬팩 1.2.0 변경 내역의 설명이 다르다. 사용하는 패치에서 시험해 본다.
- 제작 환경에서 docs.tricentis.com과 code.visualstudio.com 접속이 막혀 있었다. Tricentis 문서는 검색 결과로, VS Code 문서는 공식 문서 저장소로, 스킬팩은 GitHub에서 직접 받아 대조했다.
