## 2. 디자인 템플릿 적용

제공받은 `01_Tosca_Customer_4H_DemoWebShop.pptx`는 디자인만 쓰고 내용은 쓰지 않았다.

- 원본에서 슬라이드를 모두 뺀 기반 파일(`src/template/tricentis_base.pptx`)을 만들고, 그 위에 46장을 새로 만들었다. 남긴 것은 슬라이드 마스터, 레이아웃 22종, 테마(색·글꼴), 마스터·레이아웃이 쓰는 이미지 7개뿐이다. 원본 슬라이드의 문장, 표, 그림, 발표자 노트는 들어가지 않는다.
- 쓴 레이아웃: Title Slide(표지), Section Header(파트 구분 4장과 휴식), Title Only, Comparison, Three Content.
- 원본의 배치 규칙을 따랐다: 제목 위치·크기·색(31pt, 004C97), 본문 회색(4E4F51), 청록·연두 규칙선 3단 구성, 남색 머리행 표, 번호 사각형 목록, LAB 화면(목표 띠, 진행 순서, 완료 확인 상자, 시간 표시), 각주와 워크북 참조 표시, 꼬리말과 쪽 번호(자동 번호 필드). 한글 글꼴도 원본과 같은 Noto Sans CJK KR이다.
- 원본은 글자가 커서 한 장에 담는 양이 적다. 그래서 33장이던 슬라이드를 46장으로 나눴다(Lab마다 개요 한 장, 프롬프트 한 장). 시간표와 워크북의 슬라이드 번호도 같이 고쳤다.
- 슬라이드 문장은 "~합니다"체로 맞췄다.
- 원본 파일에 남아 있던 메타데이터를 지웠다: 다른 문서의 슬라이드 제목 목록(`docProps/app.xml`), 작성자·작성일, 미리보기 그림, 변경 기록 연결, 구역 목록. 작성일과 장 수는 빌드할 때 새로 기록한다.

## 3. 자동 검증 (`src/verify.py`, 62개 항목 전부 통과)

- 교육자료의 도구 32개가 스킬팩 `reference/tools-index.md`와 정확히 일치
- 본문에 나오는 도구·파라미터 이름(snake_case)이 모두 실제 이름 (파일·문서 이름 3개는 예외 목록에 넣음)
- T01~T18이 가리키는 워크플로 파일 18개가 모두 존재하고, 순서가 `workflows-index.md`와 같음
- 실습 프롬프트 14개와 템플릿 19개(T00 포함)가 슬라이드와 워크북에 같은 문구로 들어 있음
- 46장 모두 발표자 노트 있음
- 이모지, 문장 속 줄표(—, 띄운 –), 느낌표, 상투적 과장 표현 없음. 시간 범위(00:55–01:10)의 붙은 – 는 시간 표기라 허용

두 파일 모두 Office 스키마 검사(validate.py)를 통과했다.

## 5. 독립 검토 결과와 조치

제작자와 별도로 검토자가 두 파일 전문을 공식 스킬팩과 대조했다. 지적 사항과 조치는 다음과 같다.

| 지적 | 조치 |
|------|------|
| "MCP는 모듈을 만들지 않는다"는 틀림 (create_api_module이 있음) | "화면을 스캔해 UI 모듈을 만들지 못한다"로 전부 수정 |
| 프롬프트 2-1의 작업 상태 변경이 Commander를 멈출 수 있음 | set_attribute로 바꾸라는 문장 추가, T00 규칙 5와 부록 B 확대 |
| Lab 4 프롬프트가 저장 없이 실행 → 바꾼 값이 실행에 안 들어갈 수 있음 | 4-1, 4-2, 4-4에 "저장한 다음" 추가, 준비 항목에 이유 명시 |
| Lab 3에서 비밀번호를 프롬프트에 입력 → 클라우드 모델로 전송 | TCP 참조 `{CP[DWS_Password]}` 방식으로 변경, 강사 준비 항목 추가 |
| 5-2가 선택 체크인처럼 읽힘 | check_in_all이 체크아웃한 객체 전부에 적용된다고 명시 |
| 5-1은 대화 기록에 의존 | "한 대화창에서 진행" 안내를 워크북 사용법과 Lab 5에 추가 |
| 휴식 전 125분 연속 | 휴식을 Lab 3 뒤로 이동 |
| "현재 제공되는 템플릿 18종"이 Tricentis 제공으로 오해될 수 있음 | "공식 워크플로 18종(Tricentis 제공) + 대응 프롬프트 템플릿(이 과정에서 작성)"으로 구분 |
| "현업에서 많이 쓰는"은 근거 없음, API 사례에 템플릿 없음 | "업무에 써 볼 만한"으로 수정, API 프롬프트 예시 추가 |

| "Unknown task" 대처가 부정확 | "작업 목록을 다시 보고 정확한 이름으로" 우선, 체크아웃 대상 구분 |
| 스킬팩을 '권장'으로 표기 (README는 둘 다 필요하다고 함) | 설치 전제로 수정, VS Code·Claude Desktop 한계 안내 추가 |

| 강사 준비 자료와 실패 시 대안 없음 | 설계안에 강사 사전 준비 체크리스트, Lab 3에 완성본 복사 대안 추가 |
| 모듈 개수 표기 불일치, Lab 5 도구 목록 누락 | "모듈을 6번 끌어다 놓아", save_workspace 추가 |
| 기계적으로 읽히는 문장 (USB-C 비유, "습관 일곱 가지", 표어식 문장 등) | 지적된 문장 모두 고쳐 씀 |

반영하지 않은 것: 워크북 표 안의 짧은 서술을 모두 명사형으로 바꾸자는 의견은, 표 안은 "~한다"체, 본문은 "~합니다"체로 나누는 것이 사내 교육 문서에서 흔한 방식이라 유지했다.

## 6. 화면 점검

LibreOffice로 46장 전부와 워크북 35쪽을 이미지로 만들어 한 장씩 확인했다.

템플릿 적용 후 찾아서 고친 문제:
- 표 행 높이가 한글 줄 높이보다 낮아 글자가 잘림 → 행마다 글자 수로 높이를 계산
- LAB 화면의 완료 확인 상자가 넘침 → 항목 수에 따라 글자 크기와 상자 높이를 조정, Lab 3은 확인 항목을 4개로 정리
- T06 상세(43장)의 도구 목록 줄 수를 적게 잡아 아래 설명과 간격이 맞지 않음 → 고정폭 글꼴 기준으로 줄 수를 계산

글자 넘침 추정 경고가 남은 4장(5, 9, 24, 39장)은 화면에서 넘치지 않는 것을 확인했다(추정치가 실제보다 큼).

1차 제작본(템플릿 적용 전)에서 고친 문제: 표 셀 여백 단위 오류, 화살표 방향, 긴 제목과 Lab 표시 겹침, 워크북 템플릿 표와 본문이 페이지에서 갈라짐, 거의 빈 페이지.

미리보기는 Noto Sans KR로 렌더링했다. 실제 PowerPoint·Word에서는 줄바꿈 위치가 조금 다를 수 있다.

## 7. 교육 전에 강사가 확인할 것

- 발표 PC 글꼴: 템플릿 글꼴인 Open Sans와 Noto Sans CJK KR이 없으면 PowerPoint가 다른 글꼴로 바꿔 보여 준다. 발표 PC에서 한 번 넘겨 보며 줄바꿈을 확인한다.
- 표준 모듈 CloseBrowser의 속성 이름(Title)과 폴더 위치: 문서에서 속성 목록까지는 확인하지 못했다.
- Demo Web Shop의 로그인 실패 문구('Login was unsuccessful'): 실제 화면에서 한 번 확인한다.
- 실제 도구 목록: Commander 패치에 따라 다를 수 있으므로 Lab 0의 도구 목록 요청으로 확인한다.
- ExecutionList 실행(T08): 2026.1 문서와 스킬팩 1.2.0 변경 내역의 설명이 다르다. 사용하는 패치에서 시험해 본다.
- Claude Desktop의 스킬 설치 방법: 스킬팩 안내에 없어 사내 관리자 확인이 필요하다.
- 제작 환경에서 docs.tricentis.com 접속이 막혀 있어, Tricentis 문서 내용은 검색 결과로 확인했다. 공식 스킬팩(GitHub)은 직접 받아 대조했다.
